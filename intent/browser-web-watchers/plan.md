## Problem and evidence (read before the approach)
Read in full at origin/main 5f78de3: `skills/daily/scripts/activity_timeline.py`, `category_rules.py`, `aw_client.py`, `afk_blocks.py` (names only), `skills/daily/references/activitywatch.md`, `skills/setup/SKILL.md` step 2, `skills/daily/tests/support.py`, and the web watcher's own source (`aw-watcher-web` `background/heartbeat.ts`).

- **Addresses are read only on zoom.** `activity_timeline.py` fetches `WEB_WATCHERS` buckets only `if args.window`. `timeline()` returns `web: None` outside zoom, and the zoom rows are printed, never used to label a span. So the compact timeline, the day rollup and every unzoomed span are labelled from `(app, title)` alone.
- **The labels are ours, not the activity source's.** `activity_timeline.load_classes()` reads the AW `classes` from `/settings` and `categorize()` applies them locally to the app and the title. The activity source computes the same labels only inside its own UI and inside `category_rules.py`'s `labelled_seconds`/`labelled_by_day` (an AW query over the window bucket alone). This is what the card asked the plan to settle (D7).
- **Category terms are already one home.** A client's `**Category terms**` line in `Timesheets/.context.md` is compiled to one AW class per client (`rule_for()`: an escaped, case-insensitive alternation, matched in the app and the title separately). Shared hosts already need the tenant segment (`SHARED_HOSTS`, `address_readings()`: `dev.azure.com/<org>`), so a term that carries a path matches an address as a plain substring. No second host list is needed (US-1/AC-2).
- **What the web watcher records (source read).** One heartbeat per active tab of the browser's last-focused window, at a fixed interval and on tab activation: `{url, title, audible, incognito, tabCount}`. The heartbeat does **not** say the browser is the foreground application. A user in another application, or in another browser window, keeps getting heartbeats for the last-focused tab. That is the background-tab hazard of US-4/AC-2, and it decides D4. It also records `incognito`, so a private tab can be skipped explicitly.
- **Chromium and Edge share a bucket.** Edge and Vivaldi report as `chrome`, so `aw-watcher-web-chrome_<host>` can hold Edge and Chrome events together, with nothing in the event naming the browser. Only a renamed bucket (spec E1: `edge`) separates them. This matters for US-3/AC-3 (D8, Q1).
- **No tested URL in title for Firefox**, and Firefox window titles end `- Mozilla Firefox`, with no profile slot. The address is the only signal there.

## Approach
One change to the data flow, one to setup, and nothing to the skeleton.

1. **Read the web watchers on every run** (not only zoom). `activity_timeline.main` fetches the host's web-watcher buckets (the existing `WEB_WATCHERS` list, unchanged) and the AFK bucket's events, always. A missing bucket is answered with nothing, as today. When there are no web events, the run takes today's code path with no new key in the output (D10).
2. **Attribute at event level, before spans are built.** A new pure function `address_evidence(win_events, web_events, afk_events, classes)` in `activity_timeline.py` returns the window events with a per-slice `address_categories` set:
   - A slice is the overlap of **one browser window event** (`BROWSER_APP`, a foreground event of the window watcher, so focus is already proved) with **one web event** (D4).
   - The web event must **corroborate** the window event: its page title is a prefix of the window title (case-insensitive, trailing ` - <profile> - Microsoft Edge`, `- Google Chrome` or `- Mozilla Firefox` ignored), its `incognito` is not true, and it carries a URL. No match, no attribution. Two browsers in one minute (spec E2) are separated by `BROWSER_APP` plus this title check.
   - The slice is clipped to the **strictly not-afk** intervals of the AFK bucket (D5). Time outside them keeps its title-only label.
   - The address is `host + path` only: scheme, port, query and fragment are dropped (D11). It is matched with the **same compiled classes** the title uses (`categorize`), so Category terms (via the AW rules they compile to) are the only source (D3, US-1/AC-2).
3. **Combine the two signals per slice** (D6):
   - title cats empty, address cats non-empty → the span takes the address category (`source: address`);
   - title cats and address cats both non-empty and **disjoint** → the span keeps the title's label and is marked `conflict`, carrying both. Text output adds `!ADDR title=<A> address=<B>`. `daily` turns it into a 🔸 citing both. Never a silent choice (US-2/AC-2);
   - title cats non-empty, address empty or agreeing → unchanged.
   Spans are then built as today (merge by category, fold gaps). The rollup counts the same relabelled events, so the day totals and the spans agree.
4. **The skeleton is untouched.** `afk_blocks.py` reads only the AFK and window buckets and never imports the timeline. Nothing in this change edits it. A pinning test compares `day_skeleton()` output for every fixture day with and without web buckets, byte for byte (US-4/AC-1).
5. **Setup.** After the guided-setup build lands, the step-2 text and its check (wherever that build placed them: `setup/references/checks.md` if it exists, else `setup/SKILL.md` step 2) gain: a store link per browser family, Edge steps (open the Chrome Web Store in the Edge work profile; Edge asks to allow extensions from other stores; one click), a one-line supported statement per browser, the managed-browser pointer to `references/endpoint-security.md` (spec E6), and URL in title still marked **required** for Chromium browsers (US-4/AC-3). A new small script `skills/daily/scripts/web_watchers.py` verifies each browser by its own bucket and recent event and names the missing one (D8).
6. **Daily gains almost nothing.** One `!ADDR` bullet and one changed clause in the existing `activity_timeline.py` entry, offset by a cut elsewhere so the post-#106 5,000-word ceiling holds (T13, D12).
7. **Evidence for judged criteria.** All fixtures are synthetic: `portal.client-a.example`, `portal.client-b.example`, `news.personal.example` (reserved `.example` TLD; no client host or name ships). The S1 instrument is a **paired Firefox/Edge fixture day**: same events, same sites, same clients, once with Firefox window titles and a `firefox` web bucket and no URL in title, once with Edge titles carrying the URL in title address and a `chrome` web bucket. Per-client browser minutes and unattributed minutes are compared in one test and recorded. The reviewer reruns it. Real Edge is proven by the shared Windows end-to-end CI job (D14, T16); what CI cannot drive is stated as not verified for Atlas. Fixtures copy the real aw-watcher-web shapes (D15, T18).

## Decisions
- D1: Build starts from fresh origin/main after the check-in build and the guided-setup build (PR #108 plan) and #106 have merged; setup edits are written against the skill map that build leaves. — alternatives: build now on today's `setup/SKILL.md` (a third edit to a hotspot and a likely rebase of step 2 text). Why: the shared-context order (check-in → guided setup → web watchers) and the 5,000-word daily ceiling. If a precondition is late, T1 waits; no parallel edit of setup or daily. Flag `hotspot: skills/setup/SKILL.md` and `skills/daily/SKILL.md` on the build card.
- D2: Attribute at event level (slice a browser window event by web events), then build spans as today. — alternatives: label spans afterwards from the web rows overlapping them (a span is merged on a category, so a long uncategorized browser span would take one address's label for hours: the failure the classification reference already warns about); add the address into the window event's title string and categorize that (a second copy of every title, and `top_titles` would show it). Why: one place, and the rollup and spans cannot disagree.
- D3: Addresses match through the compiled AW classes already loaded by `load_classes()` (rules compiled from the context file's Category terms), by the same `categorize()` the title uses. No host list, no new config, no new parse of the context file. — alternatives: parse the context file in the timeline (the module docstring in `category_rules.py` says no reader should; the guided-setup plan adds one narrow parser for another purpose); a `hosts` field in the candidates JSON (a second list: forbidden by US-1/AC-2). Why: US-1/AC-2 and the atlas decision. Known cost: a user's own non-managed AW rule also applies to an address. That is the same reach it already has on titles; recorded in Risks.
- D4: Only the focused window attributes. A web event counts only where it overlaps a foreground **browser** window event and its title corroborates that window's title. — alternatives: trust any web event in an active span (a background tab or another window would attribute: US-4/AC-2 fails); use the web event's own `audible`/`tabCount` (not focus evidence). Why: the heartbeat does not carry focus; the window watcher does.
- D5: Address attribution is clipped to strictly `not-afk` intervals of the AFK bucket, a subset of the skeleton's active spans (those fold short AFK in). A new `not_afk_intervals(events)` in `aw_client.py`. — alternatives: import `afk_blocks.active_spans` (forbidden: nothing imports an entry point, `test_module_boundaries`); move `active_spans` into `aw_client.py` and rewrite `afk_blocks` (a larger change to the skeleton, which this project must not touch); no clip (an address then labels AFK time; spec US-4/AC-1). Why: stricter than the skeleton is safe, and the skeleton itself does not move. The idle decision stays the AFK watcher's alone (refusal 5).
- D6: Disagreement keeps the **title's** label on the span, adds `conflict` and both labels, prints `!ADDR`, and `daily` flags 🔸 citing both. — alternatives: address wins (silent choice); title wins with no flag (silent choice); count it as `!MULTI` (the user cannot tell which signal said what). Why: US-2/AC-2. The title label is kept only so the span has a place in the rollup; the user decides.
- D7: **The activity source's own labels** are left title-only, because they exist in two places only: the AW web UI (not ours) and `category_rules.py`'s `verify`, `dormant` and the gate. The rules written do not change at all, so `--status`, the stamp and `context_fingerprint` (the whole context file's digest) stay exactly as they are, and address attribution cannot make the rules stale. Three coherence changes keep `category_rules.py` honest for a Firefox user whose terms are address-only: (a) the gate's sample also holds each browser address (`host+path`) as one more sampled window, kept in a separate `matched_addresses`, so a term seen only in addresses is not reported `UNVERIFIED … dormant/suspect`; (b) `verify` still compares only the title matches with the activity source's answer (an address match must never produce the ERR "the activity source labels none of them"); (c) `dormant` also counts a rule alive when its regex matches that day's or an earlier day's addresses (a local match over the web events, no new AW query), so an address-only client is not reported DORMANT. — alternatives: change the AW rules to also match addresses (AW categorizes window events only, so impossible); leave the gate title-only (every Firefox client's first rebuild prints a false suspect/dormant line; the user is taught to ignore `UNVERIFIED`); a second stamp for address terms (a second home). Why: the goal is "no second list", "coherent staleness", and no new false alarms.
- D8: Setup verifies per browser with `web_watchers.py --browsers <list>`: for each named browser it prints `WEB <browser> OK <bucket> last event <N> min ago`, `WEB <browser> STALE …` or `WEB <browser> MISSING`. It uses `pick_bucket` for this host only (spec E5) and reads every `aw-watcher-web-*` bucket, so a renamed `edge` bucket is found (spec E1). Where Edge and Chrome both map to the one `chrome` bucket, a bucket cannot name its browser, so the script prints `WEB edge OK (shared chrome bucket)` only when a recent event's title is a prefix of a foreground Edge window title at that time (the same corroboration as D4), and otherwise `UNPROVEN`, with the one instruction: open any page in that browser, wait a minute, run it again. — alternatives: per-family check in prose (the criterion asks for a named missing browser, and prose is not repeatable); a bucket-per-browser assumption (false on real Edge, see Problem). Why: US-3/AC-3 and honesty about what a bucket proves.
- D9: URL in title stays required for Chromium browsers in setup's text and `skills/setup`'s check. The build records, in `docs/skills/daily/decision-log.md`, what the web watcher does and does not cover that URL in title does (below). Nothing is dropped. — Evidence in hand: URL in title's value is not only the address. It carries a **profile tag** (`[ClientA]`) for a profile dedicated to one client, which no address can replace, and the web watcher records nothing in private windows and nothing when it is not enabled or its bucket is down. On the synthetic pair the address alone does reach parity for a tab with a known host. So the finding to hand atlas is "partial, not full coverage": address covers hosts; the tag covers profile-dedicated work; Edge's profile name in the title covers the same for Edge without any extension. Real-Windows measurement is PENDING (T16). The recommendation for atlas's amendment brief is to keep the requirement.
- D10: No-web identity. With no web-watcher events, `timeline()` returns the same dict as today (no new keys), and `main()` prints the same text and JSON. All new keys exist only when at least one web event was read. Pinned by a test over every golden day and scenario. — alternatives: always emit empty new keys (breaks byte identity, US-5/AC-1).
- D11: Match host and path only (drop query and fragment). — alternatives: whole URL (a search for a client's name on a search engine, `?q=acme`, would attribute a personal search to the client: B3); host only (shared hosts cannot be told apart: spec E3). Why: personal browsing must not become billable because a word was in the URL.
- D12: The word budget for `skills/daily/SKILL.md` is measured on post-#106 main; the change adds one bullet and one clause and removes at least as many words from the same step. A size test (the one #106 adds, or a new one) is the guard. If the offset cannot be found without cutting a rule, stop and send atlas the evidence.
- D14: Windows proof is the shared end-to-end job on `windows-latest` in `.github/workflows/checks.yml` (Atlas, 2026-10-20), created by the earlier builds (check-in, guided setup). This build extends it with named steps and creates no second job. Steps: install `aw-server`, create `aw-watcher-web-firefox_<host>` and `aw-watcher-web-chrome_<host>` buckets (type `web.tab.current`) with real-shape events, run setup's per-browser verification (`web_watchers.py --browsers`), and assert Firefox and Chrome OK, Edge UNPROVEN on the shared bucket until a foreground Edge window event corroborates it, then OK; a missing browser is named. A real browser is not installed.
- D15: Fixtures copy the real aw-watcher-web shapes, read from the extension source (`src/background/heartbeat.ts`, `client.ts`): bucket `aw-watcher-web-<browser>_<host>`, bucket type `web.tab.current`, event `data` = `{url, title, audible, incognito, tabCount}` plus `profile` only when the user named a profile. Edge reports as `chrome`, so Edge and Chrome share `aw-watcher-web-chrome_<host>`; newer extension versions detect `edge` for new installs but keep `chrome` for existing ones (`helpers.ts`), so both fixture shapes exist. T18 names the source file and line each shape was copied from.
- D16: Verification is the build worktree's own venv, `.venv/bin/python -m pytest -q tests skills/daily/tests` and `.venv/bin/pyright`, plus `Checks` green on the PR head. The spec's `auto` probes read the latest completed `Checks` conclusion on main, so at the build gate the run's `headSha` must contain the build.
- D13: No ADR. Every part is reversible by reverting the commits (new keys are additive, the new script is new, the setup text is prose). Findings go in the decision log, as AGENTS.md § Where a thing goes asks.

## Risks and rollback
- **Mis-billing from a wrong attribution** (the worst failure) → D4 corroboration and focus, D5 active clip, D11 no query string, D6 flag on disagreement, and a personal-site fixture that must stay unattributed. A term that is also a word in a path (`/acme-blog`) can still match; the existing gate's share ceiling and the user's review (Step 5) are the backstops, and the daily flag lists address-attributed spans so they are reviewable.
- **A user's non-managed AW rule now also reads addresses** → same reach as on titles, shown by `!ADDR`/`source: address` in the output; recorded in the decision log. A user can read `--json` to see which spans came from an address.
- **Title corroboration too strict** (a page whose title the browser shortens) → falls back to today's title-only label: loses benefit, never mis-bills. T6 reports counts of slices dropped for no corroboration, so a fixture or real day can show the rate.
- **Extra fetch on every run** → one request per existing web bucket; a missing bucket costs nothing (`pick_bucket` → None). T4 pins output identity; an unreachable source keeps today's refusal path.
- **Collision with setup/daily edits** (check-in, guided-setup, #106, #48) → D1 ordering; rebase before T12; hotspot comments on the card. Rollback: each task is one commit; `git revert` the range. Scripts and docs only; nothing is installed on any machine and no user file is migrated. The stamp and the AW rules are not touched, so there is nothing to restore in a user's activity source.
- **Reserved boundary:** if the build finds that URL in title can be dropped, or any step would need admin rights or weaken endpoint security, stop and `kanban_block(needs_input)` to atlas.
